# 10 工程、部署与具身应用

一个离线指标良好的模型并不等于一个可靠的具身智能系统。本节整理从实验代码到在线组件时需要补齐的工程与评估环节。

## 1. 数据管线

数据管线应明确：

- 原始数据版本、许可和来源。
- 样本生成规则与唯一标识。
- 训练/验证/测试划分清单。
- 预处理参数及其拟合数据范围。
- 异常值、缺失值和损坏文件处理。
- 标签版本和人工标注协议。

数据版本应与模型检查点绑定。只保存模型权重而无法恢复训练数据和预处理流程，不算可复现。

## 2. 配置与实验追踪

配置至少应包含：

- 模型结构与初始化方式。
- 数据路径、划分和增强。
- 损失、优化器和学习率调度。
- batch size、训练步数和随机种子。
- 验证频率与最佳模型选择规则。

实验日志应记录配置、代码提交、运行环境、指标曲线和生成产物。配置文件应是实验事实的唯一来源，避免命令行、代码默认值和文档互相矛盾。

## 3. 检查点

可恢复训练的检查点通常包括：

- 模型参数。
- 优化器与调度器状态。
- 当前 epoch/step。
- 随机数生成器状态。
- 数据采样器状态（需要严格续训时）。
- 配置和最佳验证指标。

只加载权重进行推理时，应显式处理键名、形状、设备和精度不匹配。

## 4. 推理模式

推理前通常需要：

```python
model.eval()
with torch.inference_mode():
    output = model(inputs)
```

同时确保训练和推理使用完全一致的：

- 特征顺序与单位。
- resize、裁剪、归一化和 tokenizer。
- 坐标系约定。
- 序列长度、padding 和 mask。
- 输出反归一化与后处理。

许多部署错误来自接口不一致，而不是模型本身。

## 5. 性能指标

除了任务准确率，还应报告：

- 单样本延迟及 P50/P95/P99。
- 吞吐量。
- 峰值 CPU/GPU 内存或显存。
- 模型大小与参数量。
- 预处理、模型和后处理的分段耗时。
- 冷启动时间与持续运行稳定性。

测量前需要 warm-up，并在目标硬件、目标 batch size 和实际输入尺寸上测试。

## 6. 模型压缩

- 混合精度：使用 FP16/BF16 降低显存并提高吞吐。
- 量化：使用 INT8 等低精度表示权重或激活。
- 剪枝：移除不重要参数或结构。
- 蒸馏：让小模型学习大模型的软目标或中间表示。
- 缓存与批处理：减少重复计算并提高硬件利用率。

压缩后必须重新评估整体指标和关键子群，不能只检查平均精度。

## 7. 校准与不确定性

分类概率不一定等于真实正确率。可靠性图和 Expected Calibration Error 可以检查校准。

不确定性来源大致包括：

- 偶然不确定性：观测噪声或任务本身的随机性。
- 认知不确定性：训练数据不足或模型未见过当前输入。

温度缩放可以改善分类校准，但不能让模型自动识别所有分布外输入。安全系统还需要阈值、拒识、回退策略和人工接管机制。

## 8. 分布外与鲁棒性评估

应针对预期变化建立测试矩阵：

| 变化类型 | 示例 |
| --- | --- |
| 视觉 | 光照、背景、遮挡、相机噪声 |
| 几何 | 新视角、对象尺寸、相机外参变化 |
| 动力学 | 质量、摩擦、延迟、执行器误差 |
| 任务 | 新对象、新指令、不同初始状态 |

平均指标可能隐藏关键失败区域，应按场景和难度分桶报告。

## 9. 离线评估与闭环评估

离线评估使用固定数据，成本低且可重复；闭环评估让模型输出影响未来输入，更接近真实部署。

行为克隆模型即使单步误差很小，也可能因误差累积进入训练数据之外的状态。应报告：

- 任务成功率与完成时间。
- 碰撞、越界和安全干预次数。
- 扰动后的恢复能力。
- 不同初始状态下的方差。
- 长时运行稳定性。

## 10. 实时控制接口

在线系统必须明确：

- 观测时间戳及多传感器同步。
- 推理频率和控制频率。
- 输出动作的单位、范围和坐标系。
- 延迟补偿与超时处理。
- 模型输出异常时的安全动作。

模型平均延迟低于控制周期仍不够，尾延迟同样可能破坏闭环稳定性。

## 11. 上线前检查清单

- [ ] 模型、数据、配置和代码版本可追踪
- [ ] 无训练/验证/测试泄漏
- [ ] 推理预处理与训练一致
- [ ] 在目标硬件测量尾延迟和内存
- [ ] 对关键分布偏移进行分组评估
- [ ] 明确动作边界、异常检测和回退策略
- [ ] 完成离线回放与受控闭环测试
- [ ] 记录已知限制和不适用场景
